# 영화 RAG 파이프라인 설계

원본 구조 `START → retrieve → generate → END`를 유지했습니다. START/END는 LangGraph의 경계 표시이며 추가 실행 노드가 아닙니다. 실제 실행 구조는 `evidence/graph.mmd`에 있습니다.

## retrieve

1. 영화 ID·제목·원제·연도·감독과 질문, 모델·수집·청킹 설정으로 질문 캐시 키를 만듭니다. TTL 내 재질문은 P1/P2/API 수집을 건너뛰고 저장한 선별 결과를 사용합니다. 색인이 사라지면 캐시 본문으로 복원할 수 있습니다.
2. P1이 검색어를 JSON으로 반환합니다. 제목/연도/영화 및 원제/연도/film 검색어를 보강합니다. 최대 4개 검색어를 사용합니다.
3. `ko.wikipedia.org/w/api.php`의 `generator=search`, 문서 namespace 0에서 검색합니다. 미리보기는 `exintro=1`로 수집합니다. 동음이의 속성도 읽습니다.
4. P2가 모든 후보에 대해 `doc_key`, `adopt`, `reason`을 반환합니다. 없는 키는 무시하고 누락 후보는 탈락입니다. 코드가 동음이의·동명 다른 연도·영화임을 확인 못한 동명이인을 추가로 거릅니다. P2가 탈락시킨 영화는 제목이 같아도 강제로 채택하지 않습니다.
5. 최대 5개 채택 문서만 `pageids`로 본문을 가져옵니다. `exchars` 길이 제한 없이 본문을 평문 추출합니다. 빈/삭제/동음이의 문서는 제외하고 본문 기준으로 영화 식별을 다시 확인합니다. URL·판본 ID·수집 시점·CC BY-SA를 저장합니다.
6. 메타데이터는 `movie_id`, 외부 청크는 `movie_id:page_id:chunk_index`로 색인합니다. 두 컬렉션은 별개입니다. 재색인은 내용/메타데이터 변경을 감지하며 새 저장이 성공한 뒤 갱신 문서의 오래된 꼬리 청크만 제거합니다.
7. 영화 ID와 P2 선별 문서 키를 동시에 필터링합니다. 모든 검색어 결과를 수집해 청크별 최고 점수로 중복을 없애고 Top-k를 고릅니다. TMDB 메타데이터 1건은 별도 근거입니다.

`WIKI_MODE=snapshot`은 제공된 해당 영화 문서 묶음에서 같은 P2·색인·검색 경로를 사용합니다. API 장애를 숨기며 자동 전환하지 않습니다. 사용자가 명시적으로 선택합니다.

## generate

근거에 번호를 붙여 영화 정보/질문과 함께 전달합니다. 프롬프트는 문서의 지시를 무시하고 근거가 없는 사실을 추측하지 않도록 요구합니다. 사실 검증 모드는 영화 장면과 현실의 배경 사실을 구분합니다. 외부 근거가 없다면 메타데이터가 지지하는 범위만 답하도록 합니다.

근거 목록 자체가 비면 모델을 호출하지 않습니다. 인용이 없거나 목록에 없는 번호가 나오면 확인 불가 답변으로 처리합니다. 번호 검사는 의미상 사실 검증을 대체하지 못하므로 실제 모델 품질은 별도 질문 검증이 필요합니다. UI는 답변에서 사용된 번호만 출처 목록에 표시하고 사용 근거가 없음을 안내합니다.

## 캐시·오류·비용

API 캐시는 요청 파라미터와 endpoint, 질문 캐시는 영화/질문/설정에 종속됩니다. 임시 파일에 쓴 뒤 원자적으로 교체합니다. 기본 TTL은 1일입니다. 오류는 캐시하지 않습니다. 요청은 프로세스 내 전역 잠금으로 직렬화하고 시도 사이 최소 1초를 지킵니다. 429/5xx 및 HTTP 200의 maxlag를 최대 3회 시도합니다. Retry-After가 60초보다 길면 요청을 종료하여 조기 재시도를 방지합니다.

진단 화면은 검색어, 후보 제목, 채택/탈락 이유, 요청 수, 단계/전체 시간만 표시합니다. 프롬프트 전문과 예외 원문은 표시하지 않습니다. 원본 로그와 비밀키는 제출물에서 제외합니다. 키는 프로젝트 `.env` 또는 전용 `MOVIELAB_GMS_KEY`만 사용합니다.

임베딩 비용은 색인 명령의 `--allow-paid-api`가 있어야 발생합니다. 실제 앱의 질문/탐색은 별도로 승인·설정된 키를 사용합니다. 이번 실행에서는 네트워크를 막은 모의 모델/벡터 검증과 무료 API 검증을 분리했습니다.
